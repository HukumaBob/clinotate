# GPU VRAM Gauge Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show a job-scoped VRAM traffic-light gauge (green/yellow/red + exact GiB numbers) in the frame editor's tools panel, so a Track/Predict job's GPU memory pressure is visible before it crashes the worker.

**Architecture:** ml-worker's SAM2/SAM3 Celery tasks record `torch.cuda.mem_get_info()` onto the `Job` row at each existing progress checkpoint. The backend's `Job` model/schema exposes those two new fields through the already-existing `GET /jobs/{job_id}` endpoint. The frontend's existing `useJob` poll (1500ms, already running while a job is pending/running) picks the fields up with no new endpoint or polling loop. A new presentational `VramGauge` component renders a traffic-light + `X.X / Y.Y GiB` text from props; `FrameEditor`/`ToolsPanel` hold the "last known value" across job transitions so the gauge shows stale (dimmed) data between jobs instead of disappearing.

**Tech Stack:** FastAPI + SQLAlchemy + Alembic (backend), Celery + PyTorch (ml-worker, GPU-backed), React + TypeScript + Zustand + React Query + Tailwind (frontend), pytest (backend/ml-worker), vitest (frontend).

## Global Constraints

- Language: English only in all code, comments, docstrings, UI copy — no Russian in committed content.
- API contract: REST + OpenAPI auto-generated by FastAPI. The frontend TypeScript client is generated from `openapi.json` via `openapi-typescript` — never hand-roll an untyped `fetch()`. Use `apiClient` from `frontend/src/shared/api/client.ts`.
- After any backend schema/route change, regenerate `openapi.json`: `cd backend && PYTHONPATH=. uv run python scripts/export_openapi.py`. Verify with `git diff --stat openapi.json` that it changed.
- TDD: every backend task and every frontend task with logic gets a failing test before the implementation.
- `ml-worker/app/models.py`'s `Job` class is a **manually-synced duplicate** of `backend/app/jobs/models.py`'s `Job` — both map the same Postgres table but live in separate codebases with no shared migration tooling. Both must be updated together; the ml-worker side never runs Alembic (it has none) — it just needs its column list to match the columns Alembic actually created.
- Never truncate the dev `endoscopy` database.
- Only commit when explicitly instructed — this plan's steps say "commit" per task per repo convention; follow the step as written.

```python
import torch


def _record_vram_usage(job: Job) -> None:
    """Records this process's current CUDA memory usage onto the Job row,
    as a percentage-of-total traffic-light metric the frontend renders
    live while a job is pending/running (see
    docs/superpowers/specs/2026-08-05-gpu-vram-gauge-design.md).
    torch.cuda.mem_get_info() is a cheap driver query, not a memory
    operation -- safe to call at every existing progress checkpoint
    without measurably affecting job duration."""
    free_bytes, total_bytes = torch.cuda.mem_get_info()
    job.vram_used_bytes = total_bytes - free_bytes
    job.vram_total_bytes = total_bytes
```

```tsx
const BYTES_PER_GIB = 1024 ** 3;

interface VramGaugeProps {
  vramUsedBytes: number | null;
  vramTotalBytes: number | null;
  isLive: boolean;
}

function thresholdColorClass(usedBytes: number, totalBytes: number): string {
  const ratio = usedBytes / totalBytes;
  if (ratio > 0.85) return "bg-red-500";
  if (ratio > 0.6) return "bg-yellow-500";
  return "bg-green-500";
}

export function VramGauge({ vramUsedBytes, vramTotalBytes, isLive }: VramGaugeProps) {
  const hasData = vramUsedBytes !== null && vramTotalBytes !== null;

  return (
    <div
      data-testid="vram-gauge"
      className={`flex items-center gap-2 text-xs text-gray-400 ${!isLive && hasData ? "opacity-50" : ""}`}
    >
      {!hasData ? (
        <span>No data yet</span>
      ) : (
        <>
          <span
            data-testid="vram-gauge-dot"
            className={`h-2 w-2 rounded-full ${thresholdColorClass(vramUsedBytes, vramTotalBytes)}`}
          />
          <span>
            {(vramUsedBytes / BYTES_PER_GIB).toFixed(1)} / {(vramTotalBytes / BYTES_PER_GIB).toFixed(1)} GiB
          </span>
        </>
      )}
    </div>
  );
}
```
