# EvaluationType Annotation Scope Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the hardcoded-string-name heuristic that decides whether an `EvaluationType` axis is a whole-frame classification or a part-of-frame mask/bbox annotation with an explicit `annotation_scope` field, fixing a bug where the sequence grid's Category dropdown was always empty.

**Architecture:** A new `AnnotationScope` enum (`frame` | `region`) becomes a required column on `EvaluationType`, threaded through the taxonomy JSON import format, the create API, the Tags admin UI, and the two frontend consumers that currently guess the mode from the evaluation type's name string.

**Tech Stack:** FastAPI + SQLAlchemy + Alembic (backend), React + TanStack Query + Vitest (frontend).

**Spec:** [docs/specs/2026-08-15-evaluation-type-annotation-scope-design.md](../../specs/2026-08-15-evaluation-type-annotation-scope-design.md)

## Global Constraints

- No Russian in committed code/comments/docs — English only.
- Dark theme only — no light-background Tailwind classes in any new UI.
- TDD: every task gets a failing test before the implementation.
- `annotation_scope` is non-nullable on `EvaluationType` — no default that could reintroduce an implicit convention.
- The taxonomy JSON import (`backend/app/taxonomy/data/imported_taxonomy.json`) must raise a clear error if a `label_type` name has no matching entry in the new `evaluation_types` array — never default or skip silently.
- Never write a hand-rolled untyped fetch — use `apiClient` from `frontend/src/shared/api/client.ts`. Never hand-edit `frontend/src/shared/api/generated/` — regenerate via `cd frontend && npm run generate-api` after backend schema changes, and regenerate `openapi.json` via `cd backend && PYTHONPATH=. uv run python scripts/export_openapi.py` first.

Open the generated file. Autogenerate will produce an `op.add_column` for a nullable or default-less enum column, which is wrong for this change (existing rows need backfilling before the column can be made NOT NULL). Replace its `upgrade()`/`downgrade()` bodies with:

```python
def upgrade() -> None:
    annotation_scope_enum = sa.Enum('FRAME', 'REGION', name='annotationscope')
    annotation_scope_enum.create(op.get_bind())
    op.add_column(
        'evaluation_types',
        sa.Column('annotation_scope', annotation_scope_enum, nullable=True),
    )
    op.execute(
        "UPDATE evaluation_types SET annotation_scope = 'REGION' "
        "WHERE name IN ('geometric', 'morphological')"
    )
    op.execute(
        "UPDATE evaluation_types SET annotation_scope = 'FRAME' "
        "WHERE name = 'frame_classification'"
    )
    op.alter_column('evaluation_types', 'annotation_scope', nullable=False)


def downgrade() -> None:
    op.drop_column('evaluation_types', 'annotation_scope')
    sa.Enum(name='annotationscope').drop(op.get_bind())
```

This backfills the three evaluation type names known to exist in the dev database at design time (see spec). If `alembic upgrade head` fails later because a row exists with a name outside this list (`annotation_scope` would remain NULL and the `alter_column` to `nullable=False` would fail with a NOT NULL violation) — that is the correct failure mode, not a bug: it means an unanticipated evaluation type exists and its scope must be decided by a human before the migration can proceed. Do not add a catch-all default.

Apply it: `cd backend && uv run alembic upgrade head`

- [ ] **Step 3: Implement the scope lookup in `import_taxonomy`**

In `backend/app/taxonomy/import_taxonomy.py`, modify `import_taxonomy()`:

```python
def import_taxonomy(session: Session, data: dict) -> None:
    procedure_by_name: dict[str, Procedure] = {}
    for name in data["procedures"]:
        procedure = session.query(Procedure).filter_by(name=name).one_or_none()
        if procedure is None:
            procedure = Procedure(name=name)
            session.add(procedure)
            session.flush()
        procedure_by_name[name] = procedure

    scope_by_evaluation_type_name: dict[str, AnnotationScope] = {
        entry["name"]: AnnotationScope(entry["scope"]) for entry in data["evaluation_types"]
    }

    label_entries_by_key = {entry["key"]: entry for entry in data["labels"]}

    # ... (unchanged: parent_keys_by_child_key construction) ...

    category_by_key: dict[str, Category] = {}
    evaluation_type_by_name: dict[str, EvaluationType] = {}
    label_by_key: dict[str, Label] = {}

    for key, entry in label_entries_by_key.items():
        # ... (unchanged: category-root skip, category resolution, category get-or-create) ...

        evaluation_type_name = entry["label_type"]
        if evaluation_type_name not in evaluation_type_by_name:
            evaluation_type = (
                session.query(EvaluationType).filter_by(name=evaluation_type_name).one_or_none()
            )
            if evaluation_type is None:
                if evaluation_type_name not in scope_by_evaluation_type_name:
                    raise ValueError(
                        f"label_type '{evaluation_type_name}' has no corresponding entry in "
                        f"evaluation_types -- add its scope before importing"
                    )
                evaluation_type = EvaluationType(
                    name=evaluation_type_name,
                    annotation_scope=scope_by_evaluation_type_name[evaluation_type_name],
                )
                session.add(evaluation_type)
                session.flush()
            evaluation_type_by_name[evaluation_type_name] = evaluation_type
        evaluation_type = evaluation_type_by_name[evaluation_type_name]

        # ... (unchanged: label get-or-create) ...

    session.commit()
```

Only the `scope_by_evaluation_type_name` dict construction (new, near the top) and the `if evaluation_type is None:` block (adds the `if evaluation_type_name not in scope_by_evaluation_type_name: raise ValueError(...)` check and passes `annotation_scope=` to the constructor) change. Everything else in the function stays exactly as it was.
