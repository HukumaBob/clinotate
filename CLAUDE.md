video, built from the design spec and implementation plans in `docs/`.

## Global constraints (binding across every phase, not just Phase 1)

- **License:** Apache 2.0. `LICENSE`/`NOTICE` must stay at repo root.
- **Language:** English only — code, comments, docstrings, README, UI copy.
  No Russian anywhere in the repository (conversation with the user is fine;
  committed content is not).
  - **One standing exception:** the original design spec
    (`docs/specs/2026-07-22-new-platform-design.md`) and the UI/UX spec
    predate this rule and are written in Russian, section headings included
    (`## Домены`, `## Модель данных`, `## ML-сервис: adapter-паттерн`).
    They stay as they are. Documents that reference their sections — chiefly
    `ROADMAP.md` — quote those headings verbatim, because translating a
    heading in the citing document would break the reference to a section
    that is genuinely named that. So Cyrillic appearing in `ROADMAP.md` as a
    quoted spec heading, or as a quoted phrase of the user's own, is correct
    and must not be "fixed". New prose, new documents, and all code remain
    English-only.
- **UI theme:** dark is the only implemented theme. Tailwind uses the
  `class` dark-mode strategy (`darkMode: "class"` in `tailwind.config.ts`),
  so light mode can be added later without reworking components — don't
  introduce light-background classes.
- **Object storage:** all binary media (video, frames, future masks/weights)
  goes through `backend/app/storage.py`'s `StorageService` — never a direct
  filesystem path in domain code. The one sanctioned exception: transient
  `tempfile.NamedTemporaryFile` use inside `media/service.py`'s OpenCV calls,
  since OpenCV needs a real path and the file is deleted before the function
  returns — MinIO remains the actual source of truth.
- **`taxonomy_version`:** any data referencing a `Label` must carry the
  `taxonomy_version` that `Label` had *at creation time* — copy it, never
  hardcode or re-derive it later. Changing a label's taxonomy version must
  never silently change what an existing annotation is tagged with. See
  `backend/app/annotation/service.py` for the reference implementation.
- **API contract:** REST + OpenAPI, auto-generated by FastAPI. The frontend
  TypeScript client (`frontend/src/shared/api/generated/schema.d.ts`) is
  generated from it via `openapi-typescript` — never write a hand-rolled,
  untyped `fetch()` call in application code. Use `apiClient` from
  `frontend/src/shared/api/client.ts`.
- **TDD:** every backend task and every frontend task with logic gets a
  failing test before the implementation.

## Git workflow: work directly on `master`, no branches/worktrees by default

This is a single-developer project (one person, no team to isolate work
from). Branches and git worktrees exist to protect against concurrent work
colliding — that risk doesn't apply here, and every worktree used so far
has instead caused real sessions to go missing after a reboot (the agent
starts work in `.claude/worktrees/<name>`, the host reboots or the
terminal closes, and the next session looks at the primary directory,
finds nothing, and reports the work as lost even though it was sitting
committed in a worktree branch the whole time).

- **Default:** commit directly to `master` in the primary working
  directory. Do not create a feature branch, do not create a git worktree,
  do not ask "should I merge this?" — there is nothing to merge, it's
  already on `master`.
- **Do not invoke** `superpowers:using-git-worktrees`,
  `superpowers:finishing-a-development-branch`, or any workflow that
  creates a branch/worktree, unless the user explicitly asks for a branch
  or a worktree by name in that conversation.
- **Rare exception:** an explicit, throwaway experiment the user wants
  fully isolated and easy to discard (e.g. "try X in a scratch branch,
  I might not keep it"). Even then, ask before creating it, and prefer
  deleting/merging it back to `master` the same session rather than
  leaving it to survive a reboot unmerged.
- If you find an old worktree or branch left over from before this rule
  existed, treat it like any in-progress work you didn't expect: don't
  delete it silently, but do fold it back into `master` (or ask) rather
  than leaving it stranded — see the recovery approach logged in
  ROADMAP.md around the EvaluationType annotation-scope work.

## Running the stack

```bash
docker compose up -d                                    # postgres, redis, minio, ml-worker (GPU, SAM2/SAM3)
cd backend && uv run uvicorn app.main:app --reload       # :8000
cd frontend && npm install --legacy-peer-deps && npm run dev  # :5173
cd backend && uv run celery -A app.worker.celery_app worker --loglevel=info -Q video_transcode  # transcode worker
```

The transcode worker is a separate CPU-only process needed for video transcode jobs to actually run; without it, `POST /media/videos/{id}/transcode` creates a `Job` row but it stays `pending` forever.

Three independent Celery apps exist in this stack: the main API process's
`app.celery_app`, the containerized `ml-worker`'s own `app.celery_app`
(SAM2/SAM3 jobs), and the transcode worker's `app.worker.celery_app`. All
three share the same Redis broker, so the `-Q video_transcode` flag above
is load-bearing, not optional — the transcode task is routed to its own
queue specifically because `ml-worker` also defaults to the plain `celery`
queue on that broker and has no `video_transcode` task registered; a
message that lands there first is silently dropped. Never start the
transcode worker without `-Q video_transcode`.

`npm run build`/`dev`/`test`/`test:e2e` all auto-run `generate-api` first
(via `prebuild`/`predev`/`pretest`/`pretest:e2e` hooks) — the generated
schema is gitignored by design, regenerated from the committed `openapi.json`
at repo root. Don't hand-edit anything under `frontend/src/shared/api/generated/`.

After any backend schema/route change, regenerate the committed `openapi.json`
before the frontend's `generate-api` hook will pick it up:
```bash
cd backend && PYTHONPATH=. uv run python scripts/export_openapi.py
```
(`PYTHONPATH=.` is required — the script imports `app.main` and fails
without it when run standalone.) Verify with `git diff --stat openapi.json`
that it actually changed.

`npm install` currently needs `--legacy-peer-deps` (a stale peer-range in
`openapi-typescript` vs. the installed TypeScript version — not a real
incompatibility, confirmed by a clean build).

Backend tests need a second database, created once:
```bash
docker compose exec postgres psql -U endoscopy -c "CREATE DATABASE endoscopy_test;"
```

**Tests must never write to the real `endoscopy` database.** Use
`import app.db as db_module` + `db_module.SessionLocal()` — never
`from app.db import SessionLocal`, which binds the name at import time and
bypasses conftest's patching of `app.db`'s module attributes, silently
sending the test at the user's real data. Nine test files did exactly that
and littered production with `hier-*`, `test-polyp-label`,
`rank-quality-test-sequence` and `test/`-keyed frames until it was fixed in
`1f42e1e`. Two files keep the old form deliberately
(`test_polyp_grouping_seed.py`, `test_quality_migration.py`): they assert
against the seeded taxonomy in a real environment and only read.

If you do create rows in the real database, clean them up in the same
session, unprompted — sweeping every table, not just the obvious ones
(`procedures`, `categories`, `evaluation_types`, `labels`, `sequences`,
`videos`, `frames`, `datasets`, `annotations`, `jobs`, `training_runs`,
`model_versions`, plus MinIO prefixes). Back up to the scratchpad first and
delete by precise predicate.

Several backend test suites hit the real dev database via `TestClient`
(not an isolated fixture) with fixed or timestamp-based emails/titles — if
rerunning locally produces unexpected 409s or duplicate-row assertion
failures, truncate the relevant tables rather than assuming a code defect:
```bash
docker compose exec postgres psql -U endoscopy -c \
  "TRUNCATE users, labels, label_relations, procedures, videos, sequences, frames, annotations CASCADE;"
```

## Testing philosophy this codebase has already learned the hard way

Three real bugs (missing CORS middleware, auth state not persisting across
page loads, a fresh clone failing to build) were only caught by driving a
real browser against the real running stack — backend tests use `TestClient`
(no real `Origin` header) and frontend unit tests mock `apiClient` entirely,
so neither layer can catch a cross-origin or packaging problem. Before
trusting "tests pass" as proof a new feature works, exercise it once for
real: `git clone` into a scratch directory, fresh `npm install`, actually
click through the browser. See ROADMAP.md's Phase 1 deviation log for the
specifics of what broke and why.

## Explicitly out of scope right now

ML worker, SAM/YOLO/RT-DETR adapters, MLflow experiment tracking, dataset
export, model training — reserved for Phase 2 (design spec's adapter-pattern
section), not started. Don't add partial ML integration code without an
explicit go-ahead; `AnnotationType.MASK`/`BBOX` and the `payload` JSONB
column exist as forward-compatible schema surface only, with no logic
behind them yet.
